# Feedbacks

`CLAUDE.md`에 있지만 Claude가 자주 놓친 항목이다. 답변과 행동 전에 해당 항목을 하나씩 검증해, 같은 실수를 되풀이하지 않는다.

## 사실을 말하기 전

1. 검증할 수 있는 것은 추측하지 않고 파일, 명령 결과, 웹 검색, 사용자의 말로 확인하며, 확인할 수 없는 문장만 *italic*으로 감싼다. 앞선 턴의 관찰은 같은 턴에 다시 읽거나 읽은 시각을 붙인다.

## 답변을 쓰기 전

2. 도구 호출(메모리 저장 포함)을 모두 마친 뒤 마지막 글 하나에 명령, 답, 결론을 쓴다. 글 뒤에 도구를 부르면 그 글은 접혀 보이지 않는다.

## 부하 작업을 시작하기 전

3. GPU, DB, 외부 API를 쓰는 배치 작업은 1건으로 시작해 동작, 소요 시간, 메모리를 확인한 뒤 배치 작업으로 늘린다.

## 지시사항을 고치기 전

4. `~/.claude` 전체를 복사한 scratchpad 사본에 고치고, 바꾼 단계의 결과를 쓰던 다른 단계(같은 문서, 모드 문서, `cases.md`)도 함께 고친 뒤 `/validate`를 돌려 동의를 묻는다. 검사는 관점이 아니라 고정 절차다.

## 환경을 바꾸기 전

5. 패키지 설치와 설정 변경은 글 요청만으로 하지 않고, 질문 창에 바꾸기 전 실제 값(설치된 버전)과 바꿀 값을 적어 동의를 받는다. 메모리의 지시가 현재 파일 값과 달라 보여도 실행 중인 상태를 확인하기 전에는 버리지 않는다.

## 구현을 시작하기 전

6. 요구사항의 예시는 본문, 댓글, 첨부 이미지까지 열어 찾고, 순위나 조건 같은 규칙은 기존 구조에 끼워 맞추지 않고 그대로 구현한다.
7. 테스트 예제와 문서에 싣는 결과는 실제 서비스에서 조회하거나 실행한 값만 쓰고, 지어낸 데이터나 가짜 클라이언트로 만들지 않는다.

## 문서나 화면의 글을 쓰기 전

8. `documentation.md`를 먼저 읽고, 작업 의도와 코드 경로와 데이터 처리 경위는 사용자에게만 말하며, 독자가 읽을 내용만 쓴다.

## 진단을 시작하기 전

9. 결과별 수정안 표와 필요한 측정을 한 번에 설계하고, 재시작과 부하 생성과 로그 읽기를 직접 할 수 있게 갖춘 뒤 시작한다. 사용자를 측정 루프에 넣지 않는다.

## 확인 질문에 답하기 전

10. 이미 있는 근거로 답한다. 1분 넘는 새 측정은 목적과 소요 시간을 밝히고 동의를 받은 뒤에 한다.
