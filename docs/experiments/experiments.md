# Experiment guide
코드, 프롬프트, 파라미터를 바꾸고 결과를 비교할 때 읽는 문서다.
예제 수와 검토 방식은 `CLAUDE.md`의 Workflow 9번에 있다.


## 재현
1. `[필수]` 문제를 보고받으면 같은 입력부터 확보할 것.
   - 비슷한 입력이나 이미 한 번 처리된 결과로 대신하지 말 것.
   - 확보할 수 없으면 어떤 차이가 있을 수 있는지 밝히고 원본을 요청할 것.
2. `[필수]` 받은 크롭이나 일부는 전체에서 위치를 찾아 같은 영역끼리 비교할 것.


## 비교
1. `[필수]` 한 번에 변수 하나만 바꾸고, seed 같은 무작위 요소는 고정할 것.
2. `[필수]` 고친 사례만 보지 말고 같은 입력 전체에서 전후 차이를 뽑아, 새로 바뀐 곳과 사라진 변화를 모두 눈으로 볼 것.
3. `[필수]` 원본, 수정 전, 수정 후를 나란히 놓은 그림으로 볼 것.
4. `[필수]` 결과가 같아야 하는 변경(리팩터링)은 출력이 비트 단위로 같은지 확인할 것.


## 경계 정하기
1. `[필수]` 임계값과 상수는 지킬 사례와 고칠 사례에서 값을 재서, 두 집단이 갈리는 곳에 둘 것.
   - 갈리지 않으면 다른 특징을 찾고, 실패 사례에만 맞춘 값을 쓰지 말 것.
2. `[필수]` 규칙을 더하면 이전에 고친 사례가 다시 깨지지 않는지 전부 다시 확인하고, 사례를 테스트로 남길 것.


## 성능
1. `[필수]` 느리면 고치기 전에 단계별 시간을 재서 원인을 찾을 것.
   - 첫 실행과 이후 실행, CPU와 GPU를 나눠 잴 것.
