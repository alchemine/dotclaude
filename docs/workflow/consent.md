# Consent guide
파일 수정, 환경 변경, git 작업과 배포, 삭제, 외부 전송을 하기 전에 읽는 문서다.
동의 대상과 제외 목록은 `CLAUDE.md`의 Workflow 4번에 있다.


## 동의 질문
1. `[필수]` 질문 창도 도구 호출이라 그 턴의 앞선 글이 접히므로(`CLAUDE.md` Response format 4번), 무엇을 어떻게 바꿀지와 근거는 질문 창 안(질문과 선택지 미리보기)에 넣을 것.
   - 질문 창에 다 담기 어려우면, 설명과 출처로 턴을 끝내고 다음 턴에 질문 창을 띄울 것.
2. `[필수]` 동의 질문의 질문 줄에는 바꿀 대상과 내용의 핵심을 적고, 자세한 값은 "진행한다" 선택지의 미리보기에 둘 것.
3. `[필수]` 동의 질문의 답 항목은 "진행한다", "진행하지 않는다"로 할 것. 방법을 고르는 질문(합칠 순서 등)은 동의 질문이 아니므로 답 항목을 제안한 방법들로 하고, 그 선택은 동의를 겸하지 않는다.
4. `[필수]` 외부 전송 전에는 대상 계정과 워크스페이스를 확인할 것. 로컬 네트워크의 DB와 LLM 서버 호출은 외부 전송이 아니지만, DB 쓰기는 환경 변경으로 동의 대상이다.


## 동의 단위
1. `[필수]` 커밋 하나로 묶을 만한 수정마다 동의 질문을 하나씩 만들 것. 수정 묶음에 섞인 삭제는 그 묶음에 포함한다.
2. `[필수]` 커밋이 아닌 결과물(이슈, Notion 페이지)은 결과물 하나, 환경 변경과 삭제는 작업 하나를 단위 하나로 볼 것.
3. `[필수]` 브랜치, push, PR, merge, 릴리스, 배포 같은 git 작업의 단위는 `docs/git/git.md`의 절차를 따를 것.


## 동의의 범위
1. `[필수]` 동의는 질문 창의 선택으로만 인정할 것. 글로만 동의하면 같은 질문 창을 다시 띄울 것(사용자가 묻지 말라고 지시한 범위와 4~5번의 모드는 제외).
2. `[필수]` 동의받은 범위 안에서 검증 실패를 다시 고치는 것과, 서브에이전트가 그 범위 안에서 하는 수정은 같은 동의에 포함된다.
3. `[필수]` PM 모드에서는 티켓 시작 동의 하나가 그 티켓의 작업 전체(`docs/workflow/pm.md` "절차" 1번)를 포함하고, 보고 질문 창의 "통과한다" 선택이 merge 동의를 겸한다.
4. `[필수]` 자동 모드(`docs/workflow/pm.md` "자동 모드")에서는 그 절의 금지 목록 밖의 작업에 동의를 받지 말 것.
5. `[필수]` goal 모드(`docs/workflow/goal.md`)에서는 목표 문장을 동의로 보고, 그 문서의 "하지 않을 것" 밖의 작업에 동의를 받지 말 것.
