# Subagents guide
서브에이전트를 띄우거나 서버에 부하를 주는 호출(DB, LLM, 크롤링)을 하기 전에 읽는 문서다.


## 밝힐 것
1. `[필수]` 서브에이전트의 수, 각자 맡을 작업량, 모델을 밝힐 것. 띄우기 전에 묻는 질문 창이 있으면 그 미리보기에, 없으면 턴의 마지막 글에 적는다.
2. `[필수]` 서버에 부하를 주는 호출(LLM, DB, 크롤링 등)은 동시 요청 수를 제시하고 질문 창으로 동의를 받은 뒤에 할 것(서브에이전트가 하는 경우 포함). GitHub, Jira, Notion, 웹 검색처럼 부하가 문제되지 않는 호출은 이 규칙의 대상이 아니다.
   - 배치 작업의 1건 시험(`CLAUDE.md` Workflow 5번의 하위 항목)은 동시 요청 1이므로 동의 전에 돌리고, 그 측정값을 동의 질문의 미리보기에 넣을 것.
3. `[필수]` 사용자가 같은 서버나 GPU를 쓰는 중이면(로그나 큐에 사용자의 요청이 보이면) 1분 넘게 부하를 주는 실행을 시작하지 말고, 시작 시점을 질문 창으로 정할 것.


## 부하 지켜보기
서버에 부하를 주는 호출을 여러 건 돌리는 작업(부하 테스트, 평가 배치) 중, 1건 시험(`CLAUDE.md` Workflow 5번의 하위 항목)으로 추정한 전체 시간이 1분을 넘는 것에 적용한다.
정한 개수를 돌려 놓고 끝나기만 기다리지 않고, 소요 시간이 안정 범위 안에 있는지 계속 보다가 벗어나면 멈춘다. 소요 시간이 늘어나면 서버에 부하가 쌓이고 있다는 뜻이다.

1. `[필수]` 안정 범위는 작업마다 다르므로 정해 둔 값을 쓰지 말고, 잰 값으로 아래 네 값을 제안해 사용자와 정할 것(Table 1).

Table 1. 안정 범위의 값.

| 값 | 뜻 | 넘으면 |
|---|---|---|
| 정상 상한 | 요청 하나의 정상 소요 시간의 상한 | 그 요청을 경고 줄로 남기고 계속한다 |
| 위험 기준 | 최근 N건 평균 소요 시간의 상한 | 멈춘다 |
| 중지 기준 | 요청 하나의 소요 시간의 상한. 클라이언트 타임아웃으로 쓴다 | 멈춘다 |
| N | 최근 평균에 넣는 요청 수(e.g. 10) | - |

2. `[필수]` 아래 세 단계로 늘리고, 작은 묶음과 전체 실행 앞에서 잰 값을 보이며 안정 범위를 질문 창으로 정할 것.
   - 1건 시험: 1건의 소요 시간을 잰다.
   - 작은 묶음(10건 안팎, 정할 동시 요청 수로): 1건 값으로 잡은 임시 안정 범위로 돌려, 요청당 소요 시간의 평균과 최댓값, 묶음 전체 시간을 잰다.
   - 전체 실행: 작은 묶음의 값으로 안정 범위와 예상 전체 시간을 다시 제안해 정한 뒤 돌린다.
   - 질문 창은 그 단계의 부하 호출 동의 질문("밝힐 것" 2번)으로 하고, 잰 값과 제안한 안정 범위를 미리보기에 넣을 것. 사용자가 선택지 밖의 답으로 다른 값을 적으면 그 값으로 한다.
   - PM 모드에서는 티켓 시작 동의가 실행을 포함하므로(`docs/workflow/consent.md` "동의의 범위" 3번) 안정 범위만 질문 창으로 정할 것.
   - goal 모드와 자동 모드에서는 질문 창 대신 `docs/workflow/goal.md` Table 1의 "부하 배치의 안정 범위" 행대로 정할 것.
3. `[필수]` 실행 스크립트가 스스로 멈추게 짤 것. Claude가 보는 것은 감시 알림과 로그뿐이라, Claude가 보고 멈추면 늦을 수 있다.
   - 요청마다 진행 건수, 소요 시간, 최근 N건 평균을 한 줄씩 남길 것. 줄바꿈 없이 덮어쓰는 출력(`\r`)은 감시 명령이 실행이 끝날 때까지 줄로 받지 못하므로 쓰지 말 것.
   - 요청 하나가 중지 기준을 넘거나, 최근 N건 평균이 위험 기준을 넘거나, 오류 응답(HTTP 오류, 연결 실패)이 오면, 새 요청을 보내지 말고 진행 중인 요청을 취소한 뒤 걸린 조건과 값을 한 줄로 남기고 끝낼 것.
   - 최근 N건 평균은 N건이 쌓인 뒤부터 위험 기준과 비교할 것.
4. `[필수]` 실행은 백그라운드로 하고, 끝날 때까지 `Monitor`로 경고, 중지, 오류(예외 출력 포함), 종료 줄을 받아 볼 것. 백그라운드 실행이 끝났다는 알림만 기다리지 말 것.
   - `Monitor`는 길어야 30분 뒤 끝나므로, 실행이 남았으면 다시 걸 것.
   - 감시 명령은 로그에 새 줄이 중지 기준보다 오래 없으면 그 사실을 한 줄로 내보내게 짜고, 그 줄이 오면 스크립트가 멈추지 않았어도 Claude가 실행을 멈출 것.
5. `[필수]` 멈춘 실행은 Claude가 다시 돌리지 말고, 멈춘 조건, 처리한 건수, 처음 N건 평균과 마지막 N건 평균을 미리보기에 넣은 질문 창으로 다시 돌릴지와 동시 요청 수를 정할 것.
   - 끝까지 돈 실행은 처리한 건수, 처음 N건 평균과 마지막 N건 평균, 경고 줄 수를 턴의 마지막 글에 적을 것.
   - goal 모드와 자동 모드에서는 질문 창 대신 `docs/workflow/goal.md` Table 1의 "부하 배치가 멈춘 뒤" 행대로 할 것.


## 모델
`[필수]` 서브에이전트의 모델은 역할과 수로 정할 것.
- 결과물의 문제를 지적만 하는 검토 서브에이전트(심각도 점수를 붙인 지적 목록 포함): 수와 상관없이 `sonnet`.
- 종합이나 최종 판정처럼 결론(통과와 실패, 최종 선택)을 내는 서브에이전트: 기본 모델(모델을 지정하지 않을 때 쓰이는 모델).
- 그 밖의 서브에이전트(검토용과 결론용을 뺀 전부를 하나로 셈): 한 턴에 순차 호출까지 합쳐 2개 이상이면 모두 `sonnet`, 1개뿐이면 기본 모델. 기본 모델로 1개를 띄운 뒤 더 띄우게 되면 추가분부터 `sonnet`.
