"대상 패키지"에 적힌 ComfyUI custom node를 개발 버전과 배포 버전 사이에서 전환하세요.
패키지가 여러 개이면 "동작 방식"의 2번부터 5번까지를 패키지마다 하세요.
- 여러 패키지를 동시에 처리해도 됩니다.
- 한 패키지에서 멈출 일이 생겨도 나머지 패키지는 계속 진행하세요.

# 용어
- 기준 폴더: `~/workspace/ComfyUI/custom_nodes`
- 켜진 버전: `<기준 폴더>/<패키지>`
- 꺼진 버전: `<기준 폴더>/.disabled/<패키지>@<버전>`
- 개발 버전: `.git`이 있는 폴더입니다.
  - 꺼질 때의 이름은 `<패키지>@nightly`입니다.
- 배포 버전: `.git`이 없고 `.tracking`이 있는 폴더입니다.
  - 꺼질 때의 이름은 `<패키지>@<버전>`입니다.
  - `<버전>`은 `pyproject.toml`의 `version`에서 `.`을 `_`로 바꾼 값입니다.

# 해제하는 룰
- Workflow 4번, 5번 (질문 창으로 동의 받기)
  - 이 command의 실행을 "동작 방식"의 폴더 이동과 배포 버전 설치에 대한 동의로 보세요.
  - 그 이외의 작업에는 해제하지 마세요.

# 동작 방식
1. 패키지 이름이 하나도 없으면 멈추고 물어보세요.
2. 켜진 버전이 개발 버전인지 배포 버전인지 확인하세요.
3. `.disabled`에서 반대쪽 버전을 찾으세요.
   - 개발 버전이 없으면 아무것도 옮기지 말고 없다고 알리세요.
   - 배포 버전이 없으면 아래 명령어로 최신 버전을 설치하고 5번으로 가세요.
     - 이 명령어는 켜진 개발 버전을 스스로 `.disabled`로 옮깁니다.
     - 설치할 패키지가 여러 개이면 명령어 한 번에 `<패키지>@latest`를 모두 적으세요.
     - `COMFYUI_PATH=~/workspace/ComfyUI ~/workspace/ComfyUI/.venv/bin/python ~/workspace/ComfyUI/custom_nodes/ComfyUI-Manager/cm-cli.py install <패키지>@latest`
   - 배포 버전이 여러 개이면 어느 것을 켤지 물어보세요.
4. 켜진 버전을 `.disabled`로 옮기고, 반대쪽 버전을 `<기준 폴더>/<패키지>`로 옮기세요.
5. 옮긴 뒤에 켜진 버전을 확인해서 알리세요.
   - 개발 버전이면 브랜치를 함께 알리세요.
   - 배포 버전이면 `version`을 함께 알리세요.
6. ComfyUI를 다시 시작해야 적용된다고 알리세요.

# 금지
- 폴더를 삭제하거나 덮어쓰지 마세요.
  - 옮길 자리에 이미 폴더가 있으면 멈추고 알리세요.
- `git checkout` 등 "동작 방식"에 없는 변경을 하지 마세요.
